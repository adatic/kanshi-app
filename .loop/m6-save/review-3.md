# レビュー結果

## 指摘

### R1 [重要度: 中] 復元した貼り付け本文が、そのまま書き出すと欠落する

- 観点: 1
- 該当: apps/web/src/main.ts:337
- 内容: 貼り付け本文をマス目へ移す処理が `mode === "paste"` の場合に限られています。貼り付け欄に7字×4句を入力して再読み込みすると、本文と `pasteDirty` は復元されますが、起動時はマス目モードです。そのまま「書き出す」を押すと、復元した本文を含まない古い `doc` が書き出されます。追加されたE2Eは復元後に貼り付けタブへ移っており、この経路を確認していません。
- 提案: 復元した未反映の本文がある場合も、書き出し対象を明確に扱ってください。「貼り付け入力→再読み込み→タブを移さず書き出し」のE2Eを追加してください。

### R2 [重要度: 高] 貼り付け欄だけに入力した詩が、確認なしで消える

- 観点: 1
- 該当: apps/web/src/main.ts:334、apps/web/src/main.ts:372
- 内容: `hasWork()` は貼り付け欄の本文を調べません。新規起動後、貼り付けモードだけで本文を入力して「新しく始める」を押すと、`hasWork()` が偽になり、確認なしで `resetTo()` が本文を消去します。自動保存された本文も空で上書きされます。完了条件の「新しく始める（確認つき）」を満たしません。読み込み時の置き換え確認にも同じ判定が使われています。
- 提案: 未反映の貼り付け本文も確認対象に含めてください。貼り付け欄だけに入力した状態で、新規作成・読み込みの確認をキャンセルすると本文が保持されるE2Eを追加してください。

## 総評

完了条件を満たしていません。過去の指摘への修正は確認できましたが、貼り付け本文の復元後の書き出しと、破棄前の確認に漏れがあります。
