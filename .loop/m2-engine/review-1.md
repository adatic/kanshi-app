# レビュー結果

## 指摘

### R1 [重要度: 高] 字数超過を判定せず例外で停止する
- 観点: 1
- 該当: packages/engine/src/analyze.ts:72
- 内容: 読みの位置を `line * 7 + pos` で管理し、7字幅の座標に戻しています。8字目以降に両韻字があると実際と異なるマスを参照します。実データで `＿＿＿＿＿＿＿三` を入力すると、`Cannot read properties of undefined (reading '0')` で停止し、`length` の判定結果を返せません。
- 提案: 内部では句・位置を衝突なく管理し、字数超過でも結果を返すようにする。8字目に両韻字がある境界テストを追加する。

### R2 [重要度: 中] 同じ平仄の異体字候補が一つに決められる
- 観点: 1
- 該当: packages/engine/src/analyze.ts:27
- 内容: 押韻位置以外では平仄だけで候補をまとめ、31行目で代表の読みを一つ選んでいます。異体字候補が複数あっても同じ平仄なら、`via` の異なる候補ごとの解釈が失われます。TASKS.md の「異体字の候補ごとに読みの組み合わせを作る」を満たしていません。既存テストは平・仄の候補なので、この境界を検出できません。
- 提案: 異体字の候補を区別したまま解釈を返し、同じ平仄を持つ複数候補のテストを追加する。

### R3 [重要度: 中] 未入力を飛び越して「々」を展開する
- 観点: 3
- 該当: packages/engine/src/input.ts:32
- 内容: 未入力・不正文字を通っても `previous` が残ります。実際に `山＿々` の「々」が「山」として処理されます。「直前の字として扱う」という仕様に対して、離れた字の読みを割り当てています。
- 提案: 直前のマスが繰り返せる字かを管理し、未入力・不正文字の後の「々」を検証するテストを追加する。

### R4 [重要度: 中] 行頭・行末の空白がエラーにならない
- 観点: 3
- 該当: packages/engine/src/input.ts:25
- 内容: 行の前後の空白を削除するため、` 山 ` でも入力エラーは空です。CLAUDE.md §4.1 の「漢字以外（空白・記号）はエラーとして位置を返す」と食い違います。テストも空白を無視する挙動を期待しています。
- 提案: 空白も位置付きエラーとして扱う。貼り付け時に除去する仕様を採用する場合は、人間による仕様判断を先に記録する。

### R5 [重要度: 中] 承句・結句の韻目が未確定でも孤雁入群格を出す
- 観点: 3
- 該当: packages/engine/src/rules.ts:157
- 内容: 承句・結句の片方の韻目が `null` でも、残る片方と首句が異なれば161行目で `kogan-nyugun` を返します。DECISIONS.md の条件は「第2・4句の韻目が一致」であり、未入力などで一致を確認できない場合は条件を満たしません。表示も未確定なのに「承句・結句の韻目」と断定します。
- 提案: 第2・4句の韻目が両方確定し、一致している場合だけ出す。片方が未入力・未収録字の場合のテストを追加する。
